# Curriculum Intelligence Engine — API (v0.7, Weeks 6–7)

A local REST service over NMIMS semester syllabus booklets for curriculum committees. It compares courses and programmes, finds
overlapping and redundant content, checks prerequisites against the programme's semester structure, maps outcomes to Bloom levels
and flags emerging-topic gaps. Nothing is sent to external services.

## Run
```bash
pip install -e .[dev]                            # package: curriculum_engine
uvicorn curriculum_engine.api:app --port 8000    # interactive docs: http://localhost:8000/docs
```
Data: the parsed dataset `data/processed/courses.jsonl` (built by `python -m curriculum_engine.run data` from the NMIMS zip, or taken from
the Teams code zip; it is not in the public repository). Embeddings use `sentence-transformers/all-MiniLM-L6-v2` (downloaded once, then cached).
Thresholds and confidence values are read from the committed `results/*.json`.

## Endpoints
| Method | Path | Input | Output |
|---|---|---|---|
| GET | `/health` | – | status, engine version, encoder, data snapshot (course versions, split hash) |
| POST | `/compare-curricula` | `course_a` + `course_b`, **or** `programme_a` + `programme_b` | courses: overlap %, similarity, confidence, redundancy warning, common / unique topics, prerequisite check, Bloom levels. Programmes or years: courses retained, renamed or revised, removed, added |
| POST | `/map-outcomes` | `course` or a list of `outcomes` | Bloom level per outcome with confidence; the faculty K/L tag when the syllabus has one |
| POST | `/find-overlaps` | `course`, `k`, optional `programme` | the k most overlapping other courses (versions of the same course excluded) |
| POST | `/check-prerequisites` | `course` | missing-prerequisite flags (checker v2) per programme, or why the course was not checked |
| POST | `/detect-redundancy` | `programme`, optional `academic_year`, `k` | the top unit pairs of different courses that teach the same content |
| POST | `/emerging-topics` | `programme` | each verified reference topic: covered or gap, closest units, cited source |
| POST | `/modernize-curriculum` | `jds` (id, text), `courses` (2–10), `title`, optional `academic_year` | overlaps between the syllabi, JD skill themes and whether they are taught, a traceable draft syllabus (JSON + Markdown), hand-off payloads for Group 11 and Group 4 (Week 7) |
| GET | `/courses` | `q`, optional `programme`, `limit` | course versions whose name contains `q`, latest first (used by the UI) |

A **course** is given as exactly one of `{"id": "nm…"}` (dataset id), `{"name": "Machine Learning"}` (latest version; optional `programme`,
`academic_year`), or `{"text": "…"}` (raw syllabus text; add `programme` and `semester` to enable the prerequisite check).
Errors: `422` invalid body (e.g. two sources for one course), `404` unknown course id, name or programme. Full schemas: `docs/openapi.json`.

## What the confidence values mean
| Field | Meaning | Source |
|---|---|---|
| `overlap.confidence`, `find-overlaps.results[].confidence` | P(any overlap) from a logistic model on TF-IDF, MaxSim and best-unit similarity, fitted on validation pairs. A relative confidence: it is not well calibrated (see Week 4). | `results/week4/confidence_model.json` |
| `find-overlaps.results[].score` | The overlap score selected on validation in Week 4: the average percentile of TF-IDF and MaxSim among validation pairs. | `results/week6/fusion_reference.json` |
| `expected_precision` (prerequisite flags) | Share of checker-v2 flags on the test split judged correct by the reference labels. | `results/week6/prerequisites_v2.json` |
| `expected_precision` (redundancy pairs) | Precision of the top redundancy flags on the test split. | `results/week3/flag_precision.json` |
| `gap_precision` (emerging topics) | Precision of flagged gaps on the Week 3 labels. Since Week 7 coverage uses the validation-tuned unit-match threshold, which agrees far better with the labelled decisions. | `results/week3/flag_precision.json`, `results/week7/emerging_threshold.json` |
| `confidence` (Bloom) | Precision of the predicted level against faculty K/L tags on the test split. | `results/week6/bloom_confidence.json` |

All of these come from LLM-annotated reference labels (no human annotators were used), so they are indicative. Every response carries
`meta` with the engine version, the encoder and the data snapshot, so a result can always be traced to the code and data that produced it.

## Known limitations
- Only text-layer booklets are parsed; scanned booklets (and OCR) are missing, so a course reported as "removed" or a prerequisite
  reported as "not offered earlier" may sit in a booklet we could not read.
- Redundancy pairs include templated units (project or case-study units that are identical across courses); they are real text
  duplicates but rarely a curriculum problem.
- Prerequisite checker v2 raises fewer false alarms than v1 but misses more removed prerequisites (Week 6 report); review flags before acting.
- Scores support a committee; they must not be used to cut or merge courses automatically.
